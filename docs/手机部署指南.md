# 手机部署指南（只用手机，免费档）

不需要电脑，不需要自己的服务器。全程在手机浏览器里完成，大约 20–30 分钟。

默认你已经有 **Cloudflare**、**Expo**、**GitHub** 三个账号，所以从生成令牌开始。

> ## ⚠️ 先记住一件事：备份 `AGENTHUB_SECRET`
>
> `AGENTHUB_SECRET` 是用来加密你 API Key 的密钥。**生成后马上存进密码管理器备份。**
>
> **以后一旦修改（或丢失）它，已经保存的 Key 就再也无法解密**，你只能在 App 里把每个助手的 Key 重新填一遍。
>
> 它和 `AGENTHUB_TOKEN`（App 的登录令牌）是两个不同的值：令牌可以随时换，密钥不能换。

## 你一共要准备 5 个值

它们最后都填进 GitHub 的 Secrets，名字必须一字不差：

| Secret 名字 | 是什么 | 从哪来 |
| --- | --- | --- |
| `CLOUDFLARE_API_TOKEN` | 允许 GitHub 帮你部署到 Cloudflare | 第 1 步 |
| `CLOUDFLARE_ACCOUNT_ID` | 你的 Cloudflare 账户 ID | 第 1 步 |
| `EXPO_TOKEN` | 允许 GitHub 帮你发布 App | 第 2 步 |
| `AGENTHUB_TOKEN` | App 连接服务器用的访问令牌 | 第 3 步（自己生成） |
| `AGENTHUB_SECRET` | 加密 API Key 的密钥 | 第 3 步（自己生成，**要备份**） |

建议准备一个能复制粘贴的地方（备忘录或密码管理器），把每一步拿到的值先记下来。

> **关于界面说明：** 下面的按钮名称是按这几个网站写本指南时的样子写的。网站改版后位置或叫法可能略有不同，对不上时按意思找即可。

## 第 1 步：Cloudflare —— API 令牌和账户 ID

### 1.1 创建 API 令牌

1. 手机浏览器打开 <https://dash.cloudflare.com> 并登录。
2. 点右上角头像（或菜单）→ **我的个人资料（My Profile）** → **API 令牌（API Tokens）**。
3. 点 **创建令牌（Create Token）**。
4. 在模板列表里找到 **编辑 Cloudflare Workers（Edit Cloudflare Workers）**，点它右边的 **使用模板（Use template）**。
5. 这个模板默认的权限就够用。其他选项保持默认；"账户资源"选你自己的账户，"区域资源"选"所有区域"即可。
6. 点 **继续以查看摘要（Continue to summary）** → **创建令牌（Create Token）**。
7. 页面会显示令牌（一长串字符）。**这个值只显示一次**，立刻长按复制，存进备忘录，记成 `CLOUDFLARE_API_TOKEN`。

> 如果以后部署时报 `Authentication error` 或 `permission` 相关的错误，回到这里编辑令牌，确认包含"账户 → Workers 脚本 → 编辑"的权限。

### 1.2 找到账户 ID

方法一（推荐）：登录后，手机浏览器地址栏里的网址形如
`https://dash.cloudflare.com/0123456789abcdef0123456789abcdef/...`，
其中那串 **32 位的字母数字**就是账户 ID。

方法二：进入 **Workers 和 Pages（Workers & Pages）** → **概述（Overview）**，页面右侧（手机上往下滑）有 **账户 ID（Account ID）**，点复制。

记成 `CLOUDFLARE_ACCOUNT_ID`。

### 1.3 确认已经有 workers.dev 子域名（很重要）

服务器地址形如 `https://agenthub.<你的子域名>.workers.dev`。如果你从来没用过 Workers，这个子域名可能还没创建，**自动部署会因此失败**。

1. 在 Cloudflare 后台进入 **Workers 和 Pages（Workers & Pages）**。
2. 如果页面提示你**设置子域名**，按提示起一个名字（字母、数字、连字符），确认。
3. 如果已经能看到 `xxx.workers.dev` 的字样，说明已经有了，不用管。

---

## 第 2 步：Expo —— 访问令牌

1. 手机浏览器打开 <https://expo.dev> 并登录。
2. 进入 **账户设置（Account settings）** → **访问令牌（Access tokens）**。（点右上角头像或菜单可以找到账户设置。）
3. 点 **创建令牌（Create token）**，名字随便写，比如 `github-agenthub`。
4. 复制显示的令牌，存进备忘录，记成 `EXPO_TOKEN`。**同样只显示一次。**

---

## 第 3 步：生成 `AGENTHUB_TOKEN` 和 `AGENTHUB_SECRET`

这两个值要**自己生成**两串又长又随机的字符，两串必须不一样，每串至少 16 位，建议 32 位以上。

用手机自带的密码生成器：

- **iPhone**：打开"**密码**"App → 右上角 **＋** 新建密码 → 密码栏里点"**建议强密码**"，复制。
- **安卓**：Google 密码管理器（或你用的密码管理器，比如 1Password、Bitwarden）里新建一条，点"生成密码"，长度拉到 32 以上，复制。

生成后：

1. 第一串记成 `AGENTHUB_TOKEN`。
2. 第二串记成 `AGENTHUB_SECRET`。
3. **马上把两个值都存进密码管理器。** 尤其是 `AGENTHUB_SECRET`，见本文开头的提醒。

> 小建议：如果生成器可以选，**只选字母和数字**（不含符号），这样以后在 App 里粘贴时不容易出错。含符号也能用。

---

## 第 4 步：把 5 个值填进 GitHub Secrets

1. 手机浏览器打开**你要部署的仓库**（先把本仓库 Fork 到你自己的账号，再打开那个 Fork）。地址形如 `https://github.com/<你的用户名>/<仓库名>`。不要把 Secret 填到别人的仓库里。
2. 点 **Settings（设置）**。
   - 手机版页面上这个标签可能被折叠了：点标签栏最右边的 **…**，或者把浏览器切到"**桌面版网站**"。
3. 左边菜单（手机上可能要先点一个"☰"）找到 **Secrets and variables** → **Actions**。
4. 点 **New repository secret（新建仓库密钥）**。
5. **Name** 填 Secret 名字，**Secret** 填对应的值，点 **Add secret**。
6. 重复 5 次，把上面表格里的 5 个都加完：
   `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`、`EXPO_TOKEN`、`AGENTHUB_TOKEN`、`AGENTHUB_SECRET`。

> Name 一个字母都不能错，也不要加空格；Secret 的值前后不要带空格或换行。
> 添加后值不会再显示出来，这是正常的。填错了就重新添加一次同名的 Secret，会覆盖旧值。

---

## 第 5 步：在 Actions 里跑部署

部署流程已经在 `main` 上，不需要再合并一个单独的“Cloudflare 部署”PR。Fork 本身不会触发 Actions，第一次要手动跑，或再往 `main` 推一次会命中路径过滤的提交。

要跑的两个流程：

- **Deploy server to Cloudflare**：测试 → 部署 Worker → 把令牌和密钥写进 Cloudflare。它在推送到 `main` 且改动落在 `core/`、`worker/`、根目录 `package.json` / `package-lock.json` 或这个 workflow 文件时自动运行。
- **Publish App with EAS Update**：检查类型 → 关联 Expo 项目 → 发布 App。它在推送到 `main` 且改动落在 `app/` 或这个 workflow 文件时自动运行。

第一次部署（或改了 Secret、只改了文档）：

1. 仓库页面点 **Actions**。如果提示要启用 Actions，先启用。
2. 左边选 **Deploy server to Cloudflare** → **Run workflow** → 分支选 `main` → 再点绿色的 **Run workflow**。
3. 对 **Publish App with EAS Update** 再做一次。

查看进度：点进对应的运行记录。全部变成绿色对勾就成功了，大约 3–8 分钟。之后改了对应目录并推到 `main`，会自动再跑；想手动重跑就重复上面的 **Run workflow**。

---

## 第 6 步：找到服务器地址

方法一（最简单）：Actions → 点开 **Deploy server to Cloudflare** 最新一次成功的运行 → 页面最下面的 **摘要（Summary）** 里有一块"**App 里要填的服务器地址**"，形如：

```
https://agenthub.<你的子域名>.workers.dev
```

方法二：同一个运行里点开 **deploy** 任务 → 展开 **Deploy Worker** 这一步的日志，里面有这个网址。

方法三：Cloudflare 后台 → **Workers 和 Pages** → 点 **agenthub** → 页面上有访问网址。

### 自检：服务器真的在运行吗？

在手机浏览器打开：

```
https://agenthub.<你的子域名>.workers.dev/api/health
```

- 看到 `{"ok":true,"name":"AgentHub","configured":true}`：一切正常。
- `"configured":false`：令牌或密钥没配好，回到第 4 步检查 `AGENTHUB_TOKEN`、`AGENTHUB_SECRET`，然后重新运行部署流程。
- 打不开：见文末"常见问题"。

---

## 第 7 步：在手机上打开 App

App 通过 **Expo Go** 打开。先在手机应用商店安装 **Expo Go**，打开后用**同一个 Expo 账号**登录。

### 方法一：从 Expo Go 的项目列表打开（推荐）

登录后，Expo Go 的"项目"列表里应该能看到 **agenthub**，点进去选最新的更新即可打开。
（列表没出现时，下拉刷新，或确认登录的是创建 `EXPO_TOKEN` 的那个账号。）

### 方法二：用 Actions 摘要里的链接

1. Actions → 点开 **Publish App with EAS Update** 最新一次成功的运行。
2. 摘要里有一行以 `exp://u.expo.dev/...` 开头的链接。
3. 长按复制，粘贴到手机浏览器地址栏打开，应该会跳转到 Expo Go。

> 这个跳转方式我没有在真机上验证过。如果没反应，用方法一或方法三。

### 方法三：二维码（需要另一块屏幕）

摘要里还有一个"更新页面"链接，打开它（`https://expo.dev/accounts/<你的账户>/projects/agenthub/updates/...`）会有二维码。
**一部手机没法扫自己屏幕上的二维码**，需要用另一块屏幕（电脑、平板、另一部手机）显示这个页面，再用装了 Expo Go 的手机扫。没有另一块屏幕就用方法一。

### 第一次打开 App

1. 看到"连接服务器"页：
   - **服务器地址**：填第 6 步找到的网址（不带结尾的 `/`）。
   - **访问令牌**：填第 3 步生成的 `AGENTHUB_TOKEN`。
2. 点"**连接并保存**"。成功后会直接进入"演示群"。
3. 发一句 **@小橙 你好**，应该会收到回复，成员之间还会互相 @ 接力聊几轮，最多 5 轮自动停止。

之后每次改了 `app/` 里的代码并合并到 `main`，会自动发布新版本，重新打开 App 就是最新的。

## 以后怎么用

- **接入自己的模型**：App 里"新建助手"，关掉"模拟助手"，填接口地址、API Key、模型名。Key 加密保存在你自己的 Cloudflare 上。
- **换访问令牌**：GitHub 里更新 `AGENTHUB_TOKEN` 这个 Secret，重新运行部署流程，然后在 App 设置里填新令牌。
- **不要改 `AGENTHUB_SECRET`**（见开头）。

## 可选：开通文件上传（图片、PDF、代码文件）

聊天里发图片、PDF 和代码文件，文件存放在 Cloudflare 的 **R2** 里。**这一步是可选的**：不开通，上面所有功能照常使用，
只是 App 里发文件时会提示"服务器没有开通文件存储"。

> R2 在 Cloudflare 上需要单独开通，**开通时可能要求绑定付款方式**（它有免费额度，个人自用一般用不完，但具体条件以 Cloudflare 当时的页面为准）。
> 下面的按钮名称我没法在这里核实，对不上时按意思找。

1. 手机浏览器打开 <https://dash.cloudflare.com>，进入 **R2 对象存储（R2 Object Storage）**，按页面提示开通 R2。
2. 回到 **我的个人资料 → API 令牌**，编辑第 1 步创建的那个令牌，**加上一条权限**：
   `账户 → Workers R2 存储（Workers R2 Storage）→ 编辑（Edit）`，保存。（令牌的值不会变，不用改 GitHub 里的 Secret。）
3. 在 GitHub 仓库的 **Actions** 里重新运行 **Deploy server to Cloudflare**。流程会自动创建名为 `agenthub-files` 的存储桶并绑定。
4. 运行完成后看摘要：出现"文件上传：**已开启**"就成功了；如果写的是"**未开启**"，展开 **Prepare file storage (R2)** 这一步的日志看原因
   （多半是 R2 还没开通，或令牌缺少 R2 权限）。

文件限制：单个文件最多 10 MB；支持图片（PNG / JPEG / GIF / WebP）、PDF，以及常见的文本和代码文件。图片会发给支持看图的模型；
文本和代码文件的内容会直接发给模型；PDF 会先提取文字再发送（扫描件没有文字层，提取不到内容）。

## 免费额度大概够不够

个人自用的聊天量，Cloudflare Workers 免费档一般够用。每个群一个 Durable Object，群里每条消息、每次 AI 回复都会消耗少量请求和存储。免费档有每日请求数和存储上限，**具体数字以 Cloudflare 官网当前说明为准**（本指南不写死数字，避免过期）。如果额度用完，当天服务会暂停，第二天自动恢复。

## 常见问题

**Actions 显示红色叉，怎么看原因？**
Actions → 点红色的那次运行 → 点失败的任务 → 展开带红色叉的那一步，看最后几行的 `error`。

**报"GitHub Secrets 缺少 …"**
第 4 步有 Secret 没加，或名字拼错了。按报错里列出的名字补上，重新运行流程。

**报"AGENTHUB_TOKEN（或 AGENTHUB_SECRET）至少需要 16 个字符"**
生成的值太短，重新生成一个更长的。（`AGENTHUB_SECRET` 如果之前已经保存过 Key，不要换，见开头。）

**部署报 `Authentication error` / `You do not have permission`**
Cloudflare API 令牌权限不够或粘贴错了。回到 1.1 重新创建，更新 `CLOUDFLARE_API_TOKEN`。

**部署报子域名相关的错（workers.dev subdomain）**
见 1.3，在 Cloudflare 后台先把 workers.dev 子域名设置好，再重新运行。

**EAS 流程失败，提示未登录 / 令牌无效**
`EXPO_TOKEN` 没填对。回到第 2 步重新创建，更新 Secret。

**EAS 流程失败，提示项目相关的错**
流程第一次运行时会自动在你的 Expo 账号下创建名为 `agenthub` 的项目。如果你的账号下已经有同名但属于别的组织的项目，需要先在 expo.dev 里处理（改名或删除），再重新运行。

**App 提示"服务器没有开通文件存储"**
说明没有开通 R2，见上面"可选：开通文件上传"。

**App 提示"连不上服务器"**
- 先在手机浏览器打开 `.../api/health` 确认服务器是好的。
- 服务器地址要以 `https://` 开头，结尾不带 `/`，也不要多写 `/api`。
- 访问令牌必须和 GitHub 里的 `AGENTHUB_TOKEN` 完全一致。

**App 提示"访问令牌无效"**
令牌填错了。注意复制时不要带上前后的空格。

**助手回复"回复失败：接口返回 401"之类**
这是**你自己的模型接口**拒绝了请求，多半是 API Key、接口地址或模型名填错。在 App 里重新新建这个助手。

**忘了 `AGENTHUB_SECRET`，或者不小心改了**
已经保存的 Key 无法恢复。办法：把 Secret 设成新值，重新运行部署流程，然后在 App 里把需要 Key 的助手重新创建一遍。因为助手名字不能重复，而目前 App 里还没有删除助手的按钮，重新创建时请换一个名字（比如在原名后加个 2）。模拟助手不受影响。
